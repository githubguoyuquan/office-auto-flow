# PPTX 面辅料提取模块整合约定

来源对话：`01a18b7a-7192-71f0-9038-1b9e5faf6a72`。
整合分支：`feature/merge-pptx-extractor`，起点 `63946b0`。
现有源码：`/Users/guoyuququan/Documents/Codex/2026-10-30/pgn/work/windows-app`。

## 已确认的最终需求

- 在 Office Auto Flow 中增加独立业务入口“PPTX 面辅料提取”，无需 OA 登录。
- 本地多选 PPTX，所有成功文件汇总到一个可编辑 XLSX、同一工作表；单文件失败继续处理其他文件，并展示错误与核对提示。
- 用户选择一个 XLSX 模板；列数、顺序和名称由实际模板决定。第一行表头，第二行数据样式；保留模板样式，不修改源模板。
- 只填写模板已有列；无对应模板列的源字段忽略，不追加列。此要求覆盖早期“未映射字段自动追加列”的方案。
- 自动匹配常见字段，允许逐模板列手工匹配或留空；未设别名的字段在模板有同名列时原样填写。
- 应用配置中管理并保存“源字段别名 → 统一字段”；多个别名可对应同一目标，自定义规则优先于内置规则。
- 范围包含款号／模特编号、设计师、年度、季节、TAG COLOR、面料及辅料表；上下文区分面料颜色与辅料颜色。
- 支持中文、英文冒号分隔的同格字段和值；普通备注中的冒号保留。
- 支持横向、纵向合并单元格及多组颜色；缺失字段留空，缺页或关系文件缺失时尽量读取可用页，并提示。
- 输出默认保存到首个 PPTX 所在目录，名称“面辅料汇总.xlsx”，重名递增，不覆盖已有文件。
- Windows 10/11 x64，一套工作台安装包，无需客户安装 Go、Python 或 PowerPoint；沿用工作台深色界面。

## 实现边界

现有 Go 内核直接解析 PPTX 的 XML 原生表格，不是图片 OCR 引擎。图片中不可读取的表格需明确提示，不能报告提取成功。
复用 `core.go`、`template.go`、`aliases.go` 的现有算法，保留相关回归样本及测试；Win32 独立界面不接入工作台。
原工具独立保留，迁入副本后在本分支演进。

## 工作台与内核接口

- Go 无界面进程通过 UTF-8 JSON 标准输入接收命令，标准输出逐行返回 JSON；诊断写标准错误。工作台不拼接 shell 命令。
- 支持模板分析（返回表头、默认字段匹配及可选目标字段）与批量提取（输入路径、模板路径、列映射、别名规则、输出位置）。
- 批量响应包含文件级进度、成功／失败数量、核对提示和最终输出路径；最终保存继续使用防覆盖方式。
- 大型 PPTX 使用本机文件选择器传路径，不把整个文件转成 Base64 发送给本地 HTTP 服务；选择和执行时校验扩展名及文件可读性。
- 取消时终止本次子进程并清理未完成文件；退出工作台时回收所启动的内核进程。
- 模板、列匹配与别名按提取模块单独保存；任务开始后使用设置快照。
- 独立模块标识 `pptx_material_extract`。按 2026-11-17 最新要求，本整合版本暂时全部开放：客户端不要求许可证、不进行授权联网校时；保留授权实现供后续恢复。
- Windows 构建先生成 Go 无界面组件，再随 Nuitka 客户端纳入安装包；不包含私钥或签发工具。

4. 独立入口、模板匹配与别名设置界面，以及模块授权。
5. Windows 构建集成、实际样本验证和安装包交付。
